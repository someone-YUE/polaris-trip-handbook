# 内容编写细则与实测案例

## 硬约束（来自项目 AGENTS.md，不可违反）

- Python 3.10+，**仅标准库**，无 pip。前端无框架 / 无 CDN / 无构建，产物为**单文件 handbook.html**。
- 地图只用免 Key 跳转链接（高德 `uri.amap.com/search?keyword=` / 腾讯等价）。
- 不抓小红书 / 抖音。不抓评论区、不绕登录。
- **不编造**营业时间、价格、评分、预约规则、车次、航班号。
- API Key 绝不进代码 / 文档 / git。
- `plan.json` 是唯一内容源；禁止手改生成的 HTML。

## `stops` 编写要求

每个 stop 必填：`place_id, time, dwell_minutes, transport_mode, transfer_minutes, estimated_cost, practical_note, time_guard`

### `practical_note`（怎么执行）

写**具体动作**，让人照着能做。反面：`注意安全` / `根据体力调整`。

好例子：
> 从正门进先看大政殿，再走中路，最后从北门出直接打车去西塔。

### `time_guard`（什么时间必须走）

必须是**可判定的时间点或条件**。反面：`视情况而定` / `保持灵活`。

好例子：
> 12:00 必须离场，排队超过 20 分钟就先吃饭

### 空话黑名单（`validate.py` 会直接报错）

`注意安全` `根据体力` `自由活动` `视情况` `随机应变` `自行安排` `量力而行` `保持灵活` `看心情` `不限` `随意`

## 时间预算（写完自检一遍）

排 stop 时把 `dwell_minutes` + `transfer_minutes` 加起来，验证当天不超时：

```
起床时间（wake_time）
  → 首个 stop 的 time
  → 每个 stop 依次累加 (dwell + transfer)
  → 末个 stop 结束时间 必须 < sleep_time
```

**常见错误**：晚餐后还排 3 个点，结果 22:00 才走到第 2 个。
**对策**：晚餐后最多留 1-2 个点，且写明「XX:XX 必须往回走」。

## 实测案例 A：忌辣地区筛菜（赣州）

**背景**：用户明确「不能吃太辣，尽量清淡」，但选了赣州。

**查证结果**：赣州菜核心风味是「咸咸辣辣」，招牌菜**全部带辣** ——
赣南小炒鱼、醋果子炒大肠、炒田螺、烫皮（蘸辣椒酱油）、信丰萝卜饺（配辣椒酱）。

**处理方式**：不要硬按用户勾的菜名排，而是**按「天然不辣」重筛一遍**：

| 类别 | 不辣可选 | 注意 |
|---|---|---|
| 正餐 | 客家酿豆腐、荷包胙（荷叶蒸）、宁都三杯鸡（只用米酒/油/酱油焖） | 三杯鸡是安全的招牌菜 |
| 早餐 | 安远三鲜粉、瑞金牛肉汤、宁都肉丸、黄元米果 | 黄元米果默认配腊肉辣椒同炒，要点清炒版 |
| 夜市小吃 | 薯包鱼、芋包子、瓦角牛肉 | 瓦角牛肉要明确要求不辣 |
| 蘸料 | —— | **烫皮、萝卜饺默认配辣椒酱油，必须单独交代「蘸料不要辣椒」** |

**通用做法**：
1. 先查目的地饮食风格（搜索「<城市> 美食 特色 辣/清淡」）
2. 与用户限制比对，**冲突时不要沉默**，直接告诉用户
3. 在 `order_tip` 里写具体的点单话术（「不要辣」「蘸料不要辣椒酱」）

## 实测案例 B：时段约束落到文案

**背景**：用户下班后出发（傍晚）+ 返程要赶 06:52 高铁。

**处理方式**：

出发日（`kind: arrival`）：
- 文案写「白天正常上班，行李前一晚收好」「下班后直接去车站」
- stops 只留交通，不排白天项目
- 若到得早，可留一个「可选宵夜」，但写明「若还有精力」并给收摊时间

返程日（`kind: return`）：
- 不排任何景点
- **倒推时间**：06:52 发车 → 车站留 40 分钟取票安检 → 车程 25-30 分钟 → **05:30 前必须退房出发**
- `summary` 里直接写出这个倒推结果，让人一眼看到

## 实测案例 C：夜生活与作息平衡

**背景**：用户要「夜生活」，但填了「23:00 前休息」。

**处理方式**：把夜生活定义为「晚餐 → 夜市小吃 → 江边散步」，而不是「酒吧/深夜场」。
每个夜间 stop 都写明收尾时间和回程动作，如：

> 22:45 前必须往回走，23:00 前到酒店。

这样既满足诉求，又不和用户自己填的作息打架。

## `food_groups` 结构

固定三种 `category`：`专程老店` | `夜市小吃` | `连锁兜底`

每种给 2-4 个 item：
```json
{
  "place_id": "gz-panyuan",
  "why": "为什么值得去（1-2 句，说特点不说广告词）",
  "order_tip": "具体怎么点（含忌口相关的点单话术）"
}
```

## `checklists` 结构

```json
{
  "essentials": [{ "title": "身份证（3 人各自带）", "note": "为什么带 + 容易忽略的点" }],
  "confirm_ahead": [{ "title": "订 X 日高铁票", "timing": "提前 7 天", "due": "2027-01-03", "note": "具体渠道 + 价格参考" }],
  "companion_votes": []
}
```

- `confirm_ahead` 的 `due` 会驱动页面按日期显示，**必须填**（格式 `YYYY-MM-DD`）。
- v1.2 起 `companion_votes` 恒为空数组（已取消投票机制）。
