# 需求说明：旅行攻略生成器（trip-handbook-maker v1）

## 背景

我们有一份手工打磨的多城慢食攻略（沈阳—延吉—长春 9 晚），现在希望把它产品化：不是每次让 AI 重新写一段聊天答案，而是生成一份可以在旅途中打开的网页攻略，并能分享给同行、让每个人勾选自己想去的地方。

开发放在智谱 ZCode 上完成（成本考虑），运行时内容生成默认调用 DeepSeek V4 Flash 闲时 API；两者互相独立，模型可通过配置切换。

## 用户与场景

- 典型场景：多城慢食行程（如多人同行、跨 2-3 城、9 晚量级），日期与各城晚数由问卷自动推导。
- 使用场景 1：出发前生成完整攻略，发到群里，大家各自勾选想去/想吃的项目。
- 使用场景 2：行程中打开手机查看当天安排、地图跳转、酒店位置。
- 使用场景 3：行程变化时，改几个字段后重新生成，仍发给同一批人。

## 核心流程

1. 填问卷（出发地、目的地、天数、每天的起床/休息时间、风景为主还是逛吃人文为主、人数房型、预算、兴趣、忌口）。
2. 生成结构化行程数据 `plan.json`。
3. 渲染单文件 `handbook.html`。
4. 分享给同行 → 各自勾选 → 导出/导入清单合并。
5. 需要修改时用页面里的“修改行程”生成一段文字，交给 Agent 重算局部数据。

## v1 功能清单

### 必做

- 问卷页：单页 HTML 表单，可跳过，本地保存草稿，输出一段标准提示词。
- 行程骨架：按城市晚数自动分配日期，规则生成，0 token。
- 内容补全：用 LLM 生成每天的 `theme/summary/periods`、地点卡片、餐厅分类、酒店商圈建议。
- 单文件 HTML：
  - 顶部封面：路线、日期、天数、同行人数。
  - 逐日行程：早/中/晚描述 + 停留点顺序 + 换乘说明 + 高德/腾讯地图跳转。
  - 酒店模块：城市、晚数、推荐商圈结论、候选酒店卡片。
  - 美食模块：按城市分组，含“值得专程/夜市小吃/靠谱连锁兜底”和点单提示。
  - 准备清单：出行必备 + 出发前确认（预约、购票、订位日期）。
  - 同行勾选：景点/美食/酒店可勾选，导出 JSON、导入合并、复制我的选择。
  - 修改行程：文本框 + 复制给 Agent 的更新请求。
- 校验：`validate.py` 检查字段、日期一致性、占位符残留。
- 成本记录：`cost.log` 记录 token 与估算金额。

### 明确不做（v1）

- 云端部署、多人实时同步、账号体系。
- 内嵌高德 JS 地图（只做免 Key 跳转链接）。
- 图片下载与人工验图。
- 小红书/抖音数据抓取。
- Google 评分、Google 地图。
- 前端框架、构建工具、依赖安装。

## 成功标准

- 不懂代码的人也能打开生成出的 HTML 并完成勾选、导出。
- 9 晚样板与人工攻略原文的行程事实一致，没有编造的营业时间/价格。
- 生成一份攻略的运行时成本控制在 DeepSeek V4 Flash 闲时价的几分钱到一两毛钱。
- ZCode 侧代码结构清晰，后续可加内嵌地图与云端同步（见技能 `references/upgrade.md`）。
