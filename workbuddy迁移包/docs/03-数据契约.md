# 数据契约：plan.json

`plan.json` 是唯一内容源，页面只从它渲染。Schema 见 `seed/plan.schema.json`，示例见 `seed/shenyang-yanji-changchun.sample.json`。

## 顶层字段

| 字段 | 类型 | 说明 |
|---|---|---|
| `trip` | object | 标题、起止日期、天数晚数、出发地、作息、节奏 |
| `travelers` | object | 人数、同行关系、每晚房间数 |
| `transport` | object | `status` + `legs[]`（航班/高铁/城际/普速/自驾/长途汽车）+ 可选比价字段 |
| `stays` | array | 每个城市的晚数、推荐商圈、候选酒店 |
| `cities` | array | 城市顺序与晚数（用于骨架校验） |
| `days` | array | 逐日行程（日期、城市、主题、早中晚、stops） |
| `places` | array | 地点库（景点/餐厅/酒店/交通枢纽） |
| `food_groups` | array | 美食分组（专程/小吃/兜底） |
| `checklists` | object | 出行前清单、确认清单、同行勾选 |
| `sources` | array | 来源链接与核验状态 |

## trip / travelers

```json
{
  "trip": {
    "title": "沈阳延吉长春9晚慢食",
    "start_date": "2027-01-10",
    "end_date": "2027-01-19",
    "days": 10,
    "nights": 9,
    "origin": "A市",
    "rhythm": "slow-food",
    "wake_time": "自然醒（赶早市时 07:30 前）",
    "sleep_time": "23:00 前"
  },
  "travelers": { "count": 2, "groups": "示例：2 位同行", "rooms_per_night": 1 }
}
```

`rhythm` 取值（v1.4 起放宽）：
- **自由文本（推荐）**：问卷「你想怎么玩？」的原话，如 `"不想赶，一天一两个重点，主打逛吃，晚上去夜市"`。生成时据此定基调，**不要改写用户原话**。
- 旧枚举（向后兼容，仍可用）：`slow-food`（慢食为主）、`sightseeing`（风景为主）、`culture`（人文为主）、`balanced`。

校验规则：`rhythm` 非空即可；旧枚举继续通过，自由文本要求 ≥2 字符（过短给警告，不报错）。

### trip 的出发/返程时段（v1.4 新增，问卷产出）

问卷把出发与返程各拆成「日期 + 时段 + 具体时间（可选）」，用于识别下班后出发 / 上班前返程：

```json
{
  "start_period": "evening",
  "start_time": "18:30",
  "end_period": "morning",
  "end_time": "08:20"
}
```

`start_period` / `end_period` 取值：`""`（不限）| `morning` | `noon` | `afternoon` | `evening` | `night`；`start_time` / `end_time` 为 `HH:MM` 或空串。这些字段当前写在 `brief.preferences`（问卷产物）里，供生成提示词表达「抵达后起算」「返程当天不排游玩」等约束；落进 `plan.json` 时并入 `transport.legs[].departure.time` / `arrival.time` 的时段描述。

天数口径：`trip.days` 是**自然日数（含返程日）**，等于 `start_date` 至 `end_date` 的闭区间天数（本例 2027-01-10 至 01-19 共 10 天）；`trip.nights` 是总晚数，等于 `cities[]`/`stays[]` 各城晚数之和（本例 9 晚）。行程数组 `days[]` 的长度必须等于 `trip.days`，返程日独立占一天。

## transport.legs

```json
{
  "mode": "flight | high-speed-rail | intercity-rail | normal-rail | drive | coach",
  "date": "2027-01-10",
  "departure": { "city": "A市", "station": "A市机场", "time": "下午" },
  "arrival": { "city": "沈阳", "station": "桃仙机场", "time": "傍晚" },
  "status": "pending | confirmed",
  "note": "以实际出票为准"
}
```

不确定具体班次时只写城市、时段与 `status: "pending"`，不要编造车次/航班号。

`mode` 也支持组合方式，用 `+` 连接，例如 `high-speed-rail+flight`（高铁接飞机）。

## transport 的比价字段（v1.3 新增）

出行方式不再固定为飞机，用户只需给**倾向**，由 `scripts/transport.py` 按口径比价选出最优解。

```json
{
  "status": "pending",
  "legs": [ ... ],
  "preference": "any",
  "profile": "thrifty",
  "recommendation": {
    "profile": "thrifty",
    "profile_label": "省钱",
    "recommended": { "mode": "high-speed-rail", "score": 1240.0, "breakdown": "..." },
    "alternatives": [],
    "excluded": [],
    "insufficient_data": false,
    "needs_fields": []
  }
}
```

| 字段 | 取值 | 说明 |
|---|---|---|
| `preference` | `any` / `prefer-rail` / `prefer-flight` / `prefer-drive` / `allow-combo` / `rail-only` / `flight-only` | 问卷第一层「出行倾向」。`any` = 哪种划算选哪种 |
| `profile` | `thrifty` / `balanced` / `comfort` | 比价口径。`thrifty` = 省钱优先（**现阶段默认**） |
| `recommendation` | object / null | 比价结果；价表缺数据时为带 `insufficient_data: true` 的对象 |

**三档口径的语义**（详见 `scripts/transport.py` 的 `WEIGHT_PROFILES`）：

| 档 | 时间权重 | 舒适权重 | 硬约束 | 适用 |
|---|---|---|---|---|
| `thrifty` | 0（不折算） | 0 | 耗时 ≤12h | 现阶段默认：只比总花费 |
| `balanced` | 1.0 | 0.3 | ≤12h 且 ≤最快方案 3 倍 | 省钱与耗时兼顾 |
| `comfort` | 1.0 | 1.0 | ≤最快方案 1.8 倍 | 用户要「飞机+舒适」时切换 |

**评价模型**：`score = 票面×人数 + 接驳×人数 + 耗时×时间价值×人数×时间权重 − 票面×12%×(舒适分/10)×舒适权重`。
分数越低越优。任一份量缺失即「数据不足」，不猜测、不静默忽略。

**价表**：`assets/transport-fares.json`。本项目**不内置、不编造**任何价格，需填写实际查询值并写明 `source_note`；
模板可用 `python scripts/transport.py --dump-template` 生成。

## days[].stops

```json
{
  "place_id": "sy-gugong",
  "time": "09:00",
  "dwell_minutes": 180,
  "transport_mode": "打车",
  "transfer_minutes": 20,
  "distance_km": 6.5,
  "estimated_cost": "门票约 ¥50/人",
  "practical_note": "从正门进先看大政殿，再走中路，最后从北门出直接打车去西塔。",
  "time_guard": "12:00 必须离场，排队超过 20 分钟就先吃饭",
  "verify": false
}
```

硬性要求：`practical_note` 与 `time_guard` 不能为空，不能写“注意安全”“根据体力调整”这类无法执行的空话。

## places[]

```json
{
  "id": "sy-gugong",
  "type": "sight | restaurant | hotel | market | experience | transport",
  "name": "沈阳故宫",
  "address": "沈河区沈阳路171号",
  "map_url": "https://uri.amap.com/search?keyword=沈阳故宫",
  "source_url": "https://www.sypm.org.cn/",
  "hours": "08:30-17:30（周一闭馆，以官方为准）",
  "price": "约 ¥50",
  "verify": true,
  "tags": ["历史文化", "博物馆"]
}
```

- `id`：稳定 kebab-case，生成后不随文案变化。
- `map_url`：高德 `uri.amap.com/search?keyword=` 或腾讯地图等价链接。
- `verify: true`：表示动态信息需出行前复核，页面显示「待核验」。
