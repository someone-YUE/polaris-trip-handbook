# trip-handbook-maker 实施计划（参照开源 Skill 拆解后更新）

> 状态：计划稿（尚未开始编码）

## 1. 摘要

把“沈阳—延吉—长春 9 晚慢食攻略”做成一个可安装到本机 Codex 的 Skill：`trip-handbook-maker`。

- v1 交付：一个**本机可直接打开/分享的单文件 HTML 互动攻略页**，不做云端部署。
- 最终方向：后续升级为互动产品（多人点选、地图嵌入、云端分享），Skill 作为内容的生成与维护通道。
- 内容生成：DeepSeek V4 Flash API（闲时价），Key 存本机配置文件；开发在智谱 ZCode 完成（可配置切换 GLM）。
- 地图：v1 用免 Key 的高德/腾讯跳转链接；预留 `amap.web_js_key`，上云后自动升级为页面内嵌地图。
- 同行勾选：v1 本机勾选 + 导出/导入 JSON 合并，无服务器。

## 2. 已确认的用户与产品决策

- 出行样板：多城慢食行程（示例：跨 2-3 城、9 晚量级），日期与各城晚数由问卷的日期跨度自动推导。
- 多人同行时，问卷收集同行关系、人数与房型（例：大床×2 + 双床×1）；慢食主题；住宿偏好（如不订电竞酒店、只要禁烟房）同样由问卷收集。
- 问卷必须含“每天几点起床/几点休息、风景为主还是逛吃人文为主”。
- 攻略界面要可分享给同行、可各自勾选想去的地方；酒店要给出选址位置建议。
- 小红书/抖音只做**精确地点链接**与公开来源引用，不抓平台数据。
- 开源参考：借鉴问卷交互、地点库/行程引用结构、餐饮分层、三道验收顺序；不照搬其页面成品、GSAP、Google 评分与图片证据管线。

## 5. 问卷字段（v1）

### 必填/强烈建议

- 出发地、目的地（可多城市，如“沈阳→延吉→长春”）。
- 出行日期区间或天数。
- 返程城市/交通事实（已订航班/高铁时可填，如“示例城 2027-01-19 上午返程”）。
- 同行人数与关系。
- 每天预计起床时间、休息时间。
- 节奏：风景为主 / 逛吃人文为主 / 均衡偏慢食 / 由 Agent 决定。

### 可选

- 预算档与每间房价区间、每晚房间数。
- 兴趣标签（本地化：早市/夜市、博物馆、老街、自然轻徒步、泡澡洗浴、韩餐/烧烤、咖啡甜品、拍照、二人转等）。
- 特别想去、明确避开、健康/饮食/行动限制、其他说明。
- 已订交通/住宿事实（填了则显示为已确认卡片，否则为“待确认”）。

问卷输出为一段标准中文提示词；未填项由 Skill 给保守默认值，不再追问。

## 7. 内容生成管线（实施时固定顺序）

1. 用户完成问卷或粘贴 brief → `generate.py new` 生成 `trips/<slug>/input.json`。
2. 规则优先：先按“城市晚数 + 慢食主题 + 城市清单”搭骨架（沈阳 4→延吉 3→长春 2），**骨架阶段 0 token**，不调 API。
3. DeepSeek 两段式补齐内容：
   - 第一段：按 `input.json` 生成逐日 `theme/summary/periods` 草案。
   - 第二段：逐城市生成 `places/food_groups/hotel 商圈` 明细与 `stays` 建议。
   - 校验段：脚本强制 JSON 可解析、必填字段齐全、时间线与日期一致；不满足则退回重试最多 2 次。
4. 不编造实时信息：价格/营业时间/闭馆日等若种子数据里没有，写入空值并标 `verify:true`，渲染为“待核验”；来源链接仅允许放官方/大众点评/公开页面，不放抓取数据。
5. `render.py` 渲染单文件 HTML；`validate.py` 检查模板占位符残留、链接可点击、清单按钮存在。
6. 输出 `cost.log` 记录本轮 DeepSeek token 与估算金额。

## 8. 页面规格（v1 单文件 HTML）

- 移动端优先，桌面居中留白；深色/浅色跟随系统。
- 顶部：封面标题 + 日期/天数 + 路线（出发地→…→返程地）。
- “今日行程”折叠：每天显示日期、城市、主题、早/中/晚描述、停留点顺序、换乘说明、每个地点“高德地图/腾讯地图 ↗”链接、酒店/返程交接提示。
- 酒店模块：城市入住晚数、推荐商圈结论、候选酒店卡片（价格/位置说明/地图跳转）、含“待核验”标记的可选项。
- 美食模块：按城市分组（沈阳/延吉/长春），含“值得专程的店、夜市/小吃、靠谱连锁兜底”三类和点单提示。
- 准备与预订清单：出行前清单、预订确认清单（故宫预约、写真预约、洗浴电话、高铁购票日期等）。
- 同行勾选：对景点/美食/酒店候选打勾，导出 JSON；导入他人 JSON 时合并去重；支持一键复制“我的选择”文字给 Agent。
- “修改行程”区：文本框可写改动（如“第 2 晚酒店换成桂林路”），一键生成可复制给 Agent 的更新请求。
- 来源与待核验：每个卡片可展开来源链接；“待核验”内容统一黄色提示，不伪装成事实。
- 版本页脚：`trip-handbook-maker · 数据生成时间 · 由 <DeepSeek> 生成后人工复核动态信息`。

## 9. 测试与验收（实施顺序）

1. `quick_validate.py`（skill-creator）通过，无脚手架占位符。
2. 种子数据离线渲染：`render.py` 跑 `seed/shenyang-yanji-changchun.sample.json`，产出 `trips/sy-yj-cc-demo/handbook.html`；核对 9 晚、3 城市、酒店商圈、地图链接、勾选导出按钮。
3. DeepSeek 小样：用最小城市（如长春）实测 Key 与闲时价，检查 `cost.log`。
4. 完整样板：按第 2 节真实行程跑一遍，人工对照攻略原文，逐项核对日期、闭馆日与推荐酒店没有跑偏。
5. 浏览器验收：390×844 与 1440×900 视口；勾选→导出→清空→导入可恢复；模板里没有 `REPLACE_ME`/占位符残留。
6. 边界：无 Key/网络失败/限流 → 明确提示并保留已生成 JSON；断点续跑不丢 `input.json`；动态信息一律可标记待核验。

## 11. 明确不做（v1 范围边界）

- 不装原版 `build-personalized-travel-guide-open-source` 到个人 skills；只做本地只读参考。
- 不做 Google 评分、图片下载/肉眼验收、GSAP、八模块完整度、离线手绘路线。
- 不做云端部署、多人实时同步、内嵌高德地图（三者进 upgrade.md）。
- 不抓取小红书/抖音；只放精确地点链接与公开来源。
