# 愿景与路线（v1.1 之后）

> 本文档记录项目的北极星愿景与真实用户反馈驱动的迭代记录。**用户初衷（2026-09-11 明确）：做成一个微信小程序**。

## 北极星：旅行攻略生成小程序

用户输入最少的信息，自动生成可分享、可勾选的攻略：

**输入（正式版问卷/小程序按此实现；v1 问卷已含 1-3 和 6 的基础字段）**
1. 出发地 + 目的地（v1.4：同一行；目的地为必填的最后一城）
   - 可选**途经城市**：动态增行，按顺序排在目的地之前
2. 出发时间 + 返程时间（v1.4：各拆为**日期 + 时段 + 可选具体时间**，用于识别下班后出发 / 上班前返程）
   - 晚数**不由用户填写**：按日期跨度自动推导，再按各城分摊（用户填了晚数则尊重）
3. 旅游习惯：起床时间、休息时间
4. 偏好：**「你想怎么玩？」自由文本**（v1.4 起，取代原"行程节奏"枚举，越具体越好）
5. 酒店价位档（经济/舒适/高端）→ 生成时据此直接给出**唯一推荐酒店**，不做候选对比
   - v1.4：问卷该字段简化为「预算」，解释为可填每晚房价区间（按房间计价）
6. 同行与用房：
   - **同行关系**（v1.4：下拉菜单 + "其他"自填，含"独自出行"；选独自出行自动收敛为 1 人 1 间）
   - 同行人数、每晚房间数（v1 问卷已有）
   - **房型明细**：每种房型各几间（例：大床房×2 + 双床房×1）——影响推荐酒店的选择与订单拆分提示
7. **酒店设施需求**（多选，可留空）：
   - 早餐、洗衣房、健身房、停车场、机场接送服务
   - 可扩展项：泳池、亲子设施、宠物友好、无烟楼层等
   - 用途：生成酒店推荐时按"满足需求项数量"打分，结合价位档给出唯一推荐；不满足的写明"缺什么"
8. **出行方式（两层问法，v1 问卷已落地）**：
   - 第一层「倾向」（单选，必答）：不限 / 倾向高铁 / 倾向飞机 / 倾向自驾 / 允许高铁+飞机组合 / 必须高铁 / 必须飞机
   - 第二层「已定班次」（可选，文本）：仅在票已买时填；不填就由系统比价决定
   - 另有「比价口径」（v1.4：**滑块**，省钱 ←→ 舒适，中间均衡）：省钱优先（默认）/ 均衡 / 舒适优先
   - **用户不报班次、不查价格**——这是本节的关键设计取向：把"查班次比价"这件事交给系统，
     用户只表达偏好。比价逻辑见 `scripts/transport.py`（变更记录 #17）

> 实现提示：第 6/7 项落地时需在 plan.json 增加 `travelers.room_types`（房型明细）与 `stays[].requirements`（设施需求清单），并同步更新 `docs/03-数据契约.md`、`seed/plan.schema.json` 与 `references/data-schema.md`（改 schema 必须同步文档）；问卷页（intake-questionnaire）同步加输入控件。

**输出**：结构化 `plan.json` → 渲染为可分享的攻略页（逐日行程、酒店商圈、美食、地图、同行勾选）。

### 架构含义（从小程序倒推）

| 层 | v1 现状 | 小程序化需要 |
|---|---|---|
| 表单 | assets/intake-questionnaire/index.html（本地网页） | 小程序原生表单页，字段一一对应 |
| 交通比价 | scripts/transport.py（0 成本规则比价，不调 API） | 云函数跑同一套权重；价表改为服务端可更新（或接 12306/航司 API） |
| 骨架引擎 | scripts/generate.py（0 token 规则） | 移植为云函数（Python 或等价移植） |
| 内容生成 | ZCode 会话内生成 / llm.py provider 层 | 云函数调 LLM API（zhipu/deepseek），Key 在服务端，不下发前端 |
| 渲染 | 单文件 handbook.html（客户端渲染） | 两个选项：a) webview 打开云端托管的 HTML；b) 原生页面按 plan.json 渲染 |
| 勾选汇总 | 本机 localStorage + 提交文本/导入合并（v1.1） | 云数据库，直接后台汇总（v1.1 的提交交互已按此心智设计） |
| 分享 | 微信发文件/链接 | 小程序卡片分享 |

### 迁移纪律

- `plan.json` 数据契约保持稳定（`docs/03` + `seed/plan.schema.json`），它是跨端通用货币。
- 展示端逻辑（template.html 的 JS）保持"只读 plan.json 渲染"，未来可平移为小程序渲染层。
- 云端与内嵌地图遵循 `references/upgrade.md` 的路径：需要用户开通云环境 / 申请高德 Key 后再启动。
